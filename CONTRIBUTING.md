# Contributing

Contributions are welcome.

1. Open an issue for behavior changes that affect schemas, safety boundaries, or provider execution.
2. Create a focused branch and keep provider-specific logic inside its adapter.
3. Add tests for observable behavior and fixtures for new project shapes.
4. Run `npm run validate`.
5. Sign commits with `git commit -s` to certify the Developer Certificate of Origin.

Do not include credentials, provider session data, copied proprietary prompts, or unreviewed third-party skills. New providers need an official documentation link, a safe probe, an isolation statement, and contract tests.
